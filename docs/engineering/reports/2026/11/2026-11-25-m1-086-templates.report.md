**Defects found during the build (fixed before this report):**

1. The guard was first attached to `@apostrophecms/page:beforePublish`, as the design note said.
   Core emits the event from the page type module, so the rule never ran: in the first CI run an
   editor published the "Templates" parent (on the disposable CI database). Now on
   `@apostrophecms/page-type:beforePublish`.
2. A `forbidden` error would have shown core's canned text "we are saving and submitting your
   draft" on the "publish the parent first" path; the guard uses `invalid`, so the editor sees the
   project's message (checked in Chrome).
3. `placeholder()` first returned an area; used directly in `main` it produced an invalid item.
   Found by the unit test; it now returns a widget.

## Security observations

- No new route, endpoint, upload or package. One server rule that only refuses (publishing under
  two slugs), for every role, through the UI and the REST API.
- Templates and patterns stay drafts; visitors get 404 (tested logged out).
- The disposable editor's password was generated at random, used only on the local host, kept in
  the scratch folder outside the repository and deleted after; the temporary database was deleted.

## Known limitations

- A copy keeps any placeholder an editor forgets; nothing checks it before publishing.
- The "category landing" pattern (m1-079) has a hero H1; pasted into a category page it gives two
  H1 headings. Not changed (Minimal change); the owner decides (m1-087 handoff §1).
- Core shows "notfound" after moving a never-published page (core behaviour).
