## What was built

- **Pause/play button**, first among the controls when autoplay is on. A visitor's pause sticks
  (a `user` hold that only Play releases); autoplay also holds while the slideshow is off-screen
  or the tab is hidden; it starts paused under reduced motion and in edit mode. Hidden slides are
  `inert`; `aria-live` is `off` while playing and `polite` while paused; swipe with pointer
  events (`touch-action: pan-y`). One readable state: `data-assurer-slideshow-state`.
- **Banner slides**: optional eyebrow, heading, heading level (H1, H2, H3 or bold text; H2 by
  default), text (300 characters), up to 2 buttons, text position across and down, dark or light
  overlay (only on slides with text); caption kept. `sanitize` refuses more than one H1 slide in a
  slideshow. Slides share one grid cell, so text grows the slide instead of being clipped.
- **Display options** (a "Slideshow settings" tab): height Short 16:7 / Medium 16:9 / Tall 75%
  of the screen; width Content / Full (edge to edge, page width without the scrollbar); transition
  Fade / Slide; image effect None / Slow zoom; text entrance None / Fade in / Rise; controls.
  Defaults are today's look, so slideshows stored before m1-072 render as before. Full width and
  Tall do not apply in a layout column.
- **Entrance animation** (None, Fade in, Rise) through the core styles API (`class: true`
  select, `lib/motion.js`) on the layout widget and its starters, layout columns and the 10
  section widgets; one `IntersectionObserver` script (`modules/asset/ui/src/motion.js`). Nothing
  is hidden without the script, in edit mode, under reduced motion or when printing; content in
  view at page load does not animate. State: `data-assurer-enter-state`.
- **Shared buttons**: `bannerButtons()` (`lib/banner.js`) and `lib/views/BannerButtons.jsx`, used
  by the hero and the slides. The hero's stored fields are unchanged.
- **The slideshow in layout columns** (`lib/area.js`), not in nested columns.
- Demo seed: the first demo slide is a banner slide labelled "Demo".
- Docs: AGENTS.md and ARCHITECTURE.md (`lib/` tables), design note, publishing workflow guide (heading levels, pause, animation), editorial
  requirements (component status, motion), decision register D-CONTENT-22, INDEX, prompt record.

Files: `lib/banner.js`, `lib/motion.js`, `lib/views/BannerButtons.jsx` (new);
`modules/assurer-slideshow-widget/{index.js,views/widget.jsx,ui/src/index.js}`;

## Changes from the design during the build

Details in the design's §12:

1. Text entrance defaults to Rise for every slideshow (the design said None when missing), so a
   saved old slideshow does not change by itself; old slides have no text.
2. The page width variable has its own script (`page-width.js`).
3. Widgets in view at page load are shown at once, not animated.
4. The leaving slide keeps its zoomed image during the fade (`is-leaving`).
5. The slide list uses the slide heading as its title.
6. **Found in Chrome:** the full-width breakout spilled past the editor's page dialog. It now
   applies inside `.assurer-main` only; in full width, slide text lines up with the page content.
7. State attributes for tests and agents (implicit state review, below).

## Implicit state review

| State | Found | Decision |
|---|---|---|
| Slideshow playing or paused | Before: a holds set with pointer and focus; Pause did not exist, so leaving the pointer restarted autoplay | **Changed**: one set of named holds (user, pointer, focus, offscreen, hidden), one `sync()` that reflects them (timer, button label, `aria-live`, class and `data-assurer-slideshow-state`); transitions in the header comment |
| Start state | Reduced motion and edit mode were "autoplay off" with no way back | **Changed**: they start with the `user` hold, so a visitor or editor can press Play |
| Hidden slides | `aria-hidden` only, focusable | **Changed**: `inert` |
| Entrance animation | New: hidden or shown per widget, plus `assurer-motion` on `<html>` | **Explicit**: hidden only while the script's class is on `<html>`; `waiting` or `shown` in `data-assurer-enter-state`; shown is final |
| Defaults for old slideshows | Schema `def` and template fallback could differ | **Kept equal** (§12.1), so opening and saving an old slideshow changes nothing by itself |
| Edit and preview switch | Core re-renders and re-runs the players | Kept: both scripts read `apos.adminBar.editMode` on each run; the old player's timer, observer and listener stop when its element is detached |
| Candidates outside scope | The gallery lightbox and the main menu keep their state in classes and ARIA (m1-066 reviewed them) | Not changed |
