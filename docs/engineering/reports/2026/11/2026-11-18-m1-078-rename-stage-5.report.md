## Implicit state review

1. **Server stack state** (new): `mimnets-cms` running → switching (settings still `ASSURER_`,
   volumes copied or partly copied) → `mimnets-wms` running with the old stack stopped → old stack
   removed (owner). `deploy.sh` tells them apart from the settings keys, Compose labels and the
   volume label alone. Every step before the settings are written is safe to run again; once the new
   project has run, a second switch is refused with the runbook path. Decision: keep the settings
   keys as the single marker of "not switched" rather than a separate state file.
2. **Database name state** (new): `assurer` only → moved; `wms` only → nothing; both → held not
   ready. The ambiguous state is never guessed; MongoDB stays reachable so a person can decide.
   Changed during the build from "exit" to "hold" (better for the owner: no restart loop).
3. **Privilege state** of `siteAdmin`: elevated only while `assurer` exists, revoked in `finally`;
   checked after the drill.
4. **Sign-in state:** old cookies are ignored; everyone signs in once. No error page.
5. **Settings file:** two files after the switch, the live one and `.env.before-m1-078` (written
   once, git-ignored). `WMS_PREVIOUS_TAG` is dropped so `--rollback` never offers a release it
   refuses.
6. **Local developer state:** an existing `.env` keeps `data/vcl-assurer-group.db`; only the
   default for new clones changes. Recorded for the owner.
