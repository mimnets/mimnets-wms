## Implicit state review

- **Menu source** (empty list → page tree; list with a visible item → list): one rule in
  `mainMenu()`, stated in the field's help text. A list whose every page is unpublished falls
  back to the tree, never to an empty header (unit test).
- **Item visibility** follows the linked page's published state, as the footer links; the
  submenu goes with its parent (unit test).
- **Current item**: page links only. Section links never mark a page as current, so Products,
  Organizations and Services (all home sections) do not light up together on the home page. As a
  consequence, on a category page the "Products" parent is not marked as the current branch (the
  sub-item is). Accepted per design §7.
- **Stale `section` on an external link** (an editor switches the type): ignored by
  `menuFromGlobal()`, so no `https://…#x` is built from a hidden field (unit test).
- **Header button** (`showHeaderCta`) stays a separate, unchanged setting.

## Security observations

- No new endpoint. New fields are core types; external URLs must be `https://` or `http://`,
  now also in the submenu (unit test). Link text is rendered as text by JSX.
- The menu's page relationship is projected, so no page content is loaded for the header.
- Test editor password: chosen by the owner, kept in the session scratch folder outside the
  repository, typed only into the local login form; not in any tracked file or report.

## Known limitations

- A new page does not join the menu by itself once the list is filled; the help text says the
  list replaces the tree.
- In the array editor a new item shows "#n" until it is saved (core behaviour of `titleField`).
- Section links use the page's absolute URL; in the local container that is `localhost:3042`
  (the base URL), as for every page link.
- Observed, not investigated: in edit mode, after the page refreshed on Update, the desktop
  submenus showed open. Not checked whether this happens on `main` as well; visitors are not
  affected.
